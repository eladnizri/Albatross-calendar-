# ALBATROSS — ניהול בקשות לו"ז 🕊️

אפליקציית Web בקובץ יחיד לניהול בקשות אירועים (לו"ז) והוספתם ל-Google Calendar.
בנויה עבור **יחידת אלבטרוס** בעיצוב כהה ויוקרתי, תמיכה מלאה בעברית (RTL) והתאמה לנייד ולמחשב.

## מבנה הפרויקט

| קובץ | תיאור |
|------|--------|
| `index.html` | האפליקציה המלאה (HTML + CSS + JavaScript) — טופס הגשה + מסך בקרה למנהל |
| `Code.gs` | קוד ה-Backend של Google Apps Script — שומר את הבקשות ב-Google Sheet |
| `README.md` | קובץ זה |

## איך זה עובד

1. **משתמשים** ממלאים טופס בקשת לו"ז ושולחים.
2. הבקשה נשמרת ב-**Google Sheet** דרך Google Apps Script.
3. **המפקד** נכנס למסך הבקרה עם סיסמה, רואה את כל הבקשות בכרטיסיות, ולכל אחת:
   - **אשר והוסף ליומן** → נפתח קישור מוכן ב-Google Calendar עם כל פרטי האירוע, והסטטוס מתעדכן ל"אושר".
   - **דחה** → הסטטוס מתעדכן ל"נדחה".

---

## מצב הדגמה מהיר (ללא הקמה)

פשוט פתח/י את `index.html` בדפדפן. ללא הגדרת `API_URL`, הבקשות נשמרות ב-`localStorage`
של הדפדפן (רק במכשיר שלך). מתאים לבדיקה ותצוגה. סיסמת הניהול היא `albatross`.

---

## הקמה מלאה (Google Apps Script + Sheet) — צעד אחר צעד

### שלב 1 — יצירת Google Sheet
1. פתח/י [Google Sheets](https://sheets.google.com) וצור/י גיליון חדש (למשל בשם "Albatross").

### שלב 2 — הוספת הסקריפט
1. בתוך הגיליון: **Extensions → Apps Script** (תוספים → Apps Script).
2. מחק/י את הקוד לדוגמה והדבק/י את כל התוכן של `Code.gs`.
3. שנה/י את `ADMIN_TOKEN` לסיסמה חזקה משלך (שורה בראש הקובץ).
4. שמור/י (💾).

### שלב 3 — פריסה כ-Web App
1. למעלה מימין: **Deploy → New deployment**.
2. ליד "Select type" לחצ/י על גלגל השיניים ובחר/י **Web app**.
3. הגדרות:
   - **Description**: `Albatross API`
   - **Execute as**: `Me` (החשבון שלך)
   - **Who has access**: `Anyone` ← חשוב! כדי שהטופס יוכל לשלוח בקשות.
4. לחצ/י **Deploy** ואשר/י את ההרשאות (Authorize access → בחר/י חשבון → Advanced → Go to project → Allow).
5. העתק/י את כתובת ה-**Web app URL** (מסתיימת ב-`/exec`).

> ⚠️ בכל שינוי עתידי בקוד — עשה/י **Deploy → Manage deployments → עריכה → New version**,
> כדי שהכתובת תישאר זהה.

### שלב 4 — חיבור ה-HTML ל-Backend
פתח/י את `index.html` ובתחילת בלוק ה-`<script>`, בתוך אובייקט `CONFIG`:

```js
const CONFIG = {
  API_URL: "https://script.google.com/macros/s/XXXXXXXX/exec", // ← הדבק/י כאן
  ADMIN_PASSWORD: "albatross", // ← חייב להיות זהה ל-ADMIN_TOKEN שב-Code.gs
  CALENDAR_TITLE_PREFIX: "לו\"ז אלבטרוס"
};
```

- **`API_URL`** — הכתובת מ-שלב 3.
- **`ADMIN_PASSWORD`** — חייבת להיות **זהה** ל-`ADMIN_TOKEN` שהגדרת ב-`Code.gs`.

### שלב 5 — פרסום ה-HTML
העלה/י את `index.html` לכל שירות אחסון סטטי, למשל:
- **GitHub Pages** (חינם — Settings → Pages)
- Netlify / Vercel (גרירה של הקובץ)
- או פשוט שליחת הקובץ למי שצריך למלא בקשה.

## אבטחה — הערה חשובה

- `ADMIN_PASSWORD` בצד הלקוח נועד להסתרת מסך הבקרה, אך אינו סוד אמיתי (ניתן לראותו בקוד המקור).
- ההגנה האמיתית היא ב-`Code.gs`: פעולות ניהול (שליפת רשימה ועדכון סטטוס) דורשות
  את ה-`ADMIN_TOKEN` בצד השרת. מי שאין לו את הטוקן לא יכול לצפות בבקשות או לשנות סטטוס.
- לכן בחר/י **טוקן/סיסמה חזקים** ואל תשתפ/י את קובץ ה-`Code.gs`.

## מסך הבקרה — התנהגות הכרטיסים
- בקשה **ממתינה** מוצגת ככרטיס מלא עם הכפתורים "אשר והוסף ליומן" ו"דחה".
- לאחר אישור/דחייה הכרטיס **מתכווץ לשורת-פס אפורה** עם נתונים כלליים
  (שם הלו"ז, מבקש, תאריך, שעות), קישור "פתח ביומן" (לאושרו), וכפתור "↩ החזר"
  להחזרת הבקשה למצב ממתין.

## אייקון למסך הבית (Add to Home Screen)
הקבצים `manifest.json`, `icon-192.png`, `icon-512.png`, `icon-180.png`, `favicon-32.png`
מספקים אייקון של סמל היחידה בעת הוספת האתר למסך הבית בנייד (iOS/Android).
יש להשאיר אותם באותה תיקייה של `index.html`.

## שדרוג אופציונלי — הוספה אוטומטית ליומן
כרגע האישור פותח קישור "הוסף ליומן" (בחירה מכוונת, ללא OAuth). מכיוון שכבר יש Backend
ב-Apps Script, ניתן בעתיד להוסיף ל-`Code.gs` פעולה שמשתמשת ב-`CalendarApp.createEvent(...)`
כדי להוסיף את האירוע ישירות ליומן שלך ללא לחיצה — נשמח להרחיב בעת הצורך.
